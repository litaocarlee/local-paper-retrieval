# Local Paper Retrieval

给一个自然语言问题，从本地 PDF 文献库里找出能够支撑回答的页，再回到原 PDF 核对。索引里的摘录、向量命中和 Jev 判断只负责定位，不能当作证据。

## 一次提问会做什么

1. 语言模型把问题改写成几句较短的英文检索式，并保留方法名、指标和数据集。原问题也保留。
2. 全文检索用 SQLite FTS5，按 BM25 给每一句检索式返回若干页。返回的是页，不是整篇论文。
3. 这些检索式再嵌成向量，和库里已经存好的页向量做余弦比较，每一句同样返回若干页。全文检索的结果不会再嵌一次。
4. Reciprocal Rank Fusion 把两路名次合成一个顺序。某一页在某一路排第 r 名，就得到 `1/(60+r)` 分。多路都靠前的页总分更高。
5. 从合成顺序里留下最多 12 页，同一篇最多 3 页。每页附一段约 1600 字的摘录。
6. Jev 在这些摘录上做 Choice，并可以在同一次调用里给出 Noul 或 Score。TypeSafe 不可用时，改由语言模型按摘录里的证据打 0 到 3 分。
7. 对选中的页重新抽取原 PDF 的该页及前后各一页。文件与索引不一致时才重算 SHA-256。
8. 只有抽出来的文字很少，或问题指向图、表、公式、数值时，才把该页渲染出来看。
9. 先写证据卡，再写事实结论。

库里的 PDF 有增删时，`search` 会自己发现变化：只哈希新文件或改过的文件，按 SHA-256 去重，并只给还没有向量的页补向量。

## 证据卡

- 主张
- 支持程度：`direct`、`partial` 或 `not_found`
- 文档标识和标题
- PDF 页码
- 可见的章节、表或图编号
- 短原文，或明确标成转述的句子
- 不能外推的边界

Jev 的 Choice、Noul、Score 和语言模型的重排理由都不是证据。没有回到原页核对之前，不要引用索引摘录。跨篇综合要标成推断。

## 运行需要

Python，以及 Poppler 提供的 `pdftotext` 和 `pdfinfo`。查询扩展和页向量各需要一个模型接口。TypeSafe 用于 Jev，缺失时自动改走语言模型重排。
